## 关键架构决断

### 决断 1：工具是结构化自报，不是新发的特权

沿用「写入时智能、运行时克制、收件箱守门」三分哲学：工具调用 = 主演模型对"我刚演出的内容"
的结构化旁注，落地仍走与 Lua hooks / 总结管线**同一套**校验与分级。不新增强权：
不给任意 card state 写权（那是卡作者 Lua 的领地）、不给黑板任意键（仍限 `BLACKBOARD_KEYS` 四键）、
不给宫殿直写（witnesses/salience 语义太精细，直写打穿视角隔离）。

### 决断 2：捆绑式 + 轮末生效，无额外往返

工具调用与剧情文本**同报文**（assistant message 同时带 content 与 tool_calls），
宿主不在对话环内回填 tool result，轮末统一应用。理由：保住「状态树转移在轮末评估，
一轮之内 B 槽内容稳定不抖动」的红线；RP 场景工具是自报性质，fire-and-forget 不增加轮次延迟。
**唯一例外**：`ui_emit` 流式中实时触发（表情要活），事件照记、重放按序重演。

### 决断 3：工具效果是消息的衍生事件

assistant 消息体（`LogBody::Message`）存原始 tool_calls；效果不直接落 state，
由「tool_calls + 确定性校验器」在重放时投影推导。这样编辑/删除/重roll 一条带工具的消息，
旧效果回滚、新消息工具重执行**自动正确**，无需特例。人工已 accept 的提案在原消息被编辑后
**保留物化正史**（人工确认不因改历史蒸发，同「编辑重建保留收线驱动转移」原则），出处标注保留。

### 决断 4：直写/提案两档，白名单镜像 `api.*`

工具名与语义直接沿用 Lua 沙箱 API（一份心智模型，文档复用）。直写档全过 hook 增量同款校验；
提案档复用 `proposal_event` 链路进收件箱，分级与 anchors 驳回原样生效。

### 决断 5：定时器只用故事时钟，不引入真实时间

定时器 = 「声明（确定性）+ 黑板 day 推进（已有事件）」的衍生求值，**不落新事件类型**：
触发现身为 `TransitionEvent`（reason 带 `timer:` 标记）或钩子效果。真实世界时钟不参与任何求值——
它会让「编辑历史重放重算」失去确定性。线 deadline（`thread:due`）已有先例，B 包不重复造线。

### 决断 6：总结管线是安全网，不是被替换者

管线保留原样；去重在 apply 阶段做（本轮工具已写 fact.X → 管线同目标同 facet 提案丢弃）。
读查询工具（codex_get / palace_recall 需要结果回填的续写环）拆出本计划，留 Backlog——
它们付往返延迟、换 token 节省，值得单独评估，不与写通道捆绑。

### 决断 7：心理应用器单实现，三路共用

模型工具（`psyche_feel`/`psyche_intent`）、卡 hooks（C 包 `api.psyche.*`）、
总结管线（PsycheDraft 应用）共用同一个宿主侧心理应用函数（槽位 ≤3 封顶、气质衰减、
阈值 → M3.5 主动开口链路）。不对称是刻意的：工具直写是在场自我报告（有界、当轮可见），
管线心理评价走收件箱分级（事后批量评价，设计 §9.2 原文）。

### 决断 8：旁白是客观叙事声道，由宿主与模式拥有，不由角色说出

旁白（narration）是第三种消息 voice：不是任何角色的台词，不是导演指令，是"故事的画外音"。
台词体下模型**不产旁白**（旁白只在宿主拥有的时刻出现：场景接缝、阶段转移、剧场拍间）；
小说模式下旁白融于散文正文，不需要单独成条。渲染上旁白永远不进气泡——
M3.2 过渡插页（`role=system`，SessionView「居中一条，不占气泡」）是现成先例，本包把它
泛化成一等公民。摘要与记忆归属：旁白是剧情正文，进总结批次；witnesses = 在场全体
（它叙述的是"做出来的"公开层面）。

### 决断 9：小说模式 = 会话级模式开关，不是新引擎

三件已有事物的组合：① 叙事模式锁「小说体」（设计 §4.1 A1 已定义：第三人称叙述、
允许直陈心理）；② 渲染策略切散文（气泡退役，对话织在段内）；③ 段末选项管线（新）。
用户输入重新定位为**剧情走向**：点选选项 = 结构化走向；自由输入 = 走向描述，
其中引号内的直语由模型织为角色台词。v1 范围收窄：小说模式限 1v1 单场景，
群聊/剧场 × 小说的组合矩阵留后续。

### 决断 10：交互原生散文，导出才用后处理

交互式小说模式**不用**第二个模型做"角色扮演 → 小说"实时转写：双模型转写会让"演到的"
与"写出的"漂移、延迟翻倍、且小说体契约（既有设计）本就能让主演模型直接产出散文。
后处理的正确位置是**导出**：把任意已完结（或进行中的）会话事件流重放成小说文档——
台词体会话也能变成小说，这是导出视图，不改写会话本身（F4）。

## 包 A · 工具调用快通道（主体）

### A1 底座：能力配置与请求/流式通道

- `Provider`（`llm.rs:16`，providers.toml）增 `tools` 字段：`"off" | "on"`，缺省 off；
  设置页按接入点开关。`"on"` 的接入点发请求带工具 schema；provider 返回 400 类错误
  → 本次请求自动去 tools 重试一次 + `diag::record` + 界面提示（仿 `chat_stream_ratcheted`
  的降级棘轮先例）。
- `ChatMessage` 增 `tool_calls`（请求侧序列化 + 响应侧解析）；`SseParser::feed` 扩展
  tool_call 增量：按 index 键收集、arguments 字符串追加、finish 时整块交出；
  UTF-8 截断与部分 JSON 的边界单测（仿 StreamOutcome 棘轮的测法）。
- 非流式 `chat_complete` 同步支持（剧场/推理型路径共用）。
- 工具 schema 常量表进 `toolcall.rs`：≤10 个工具、紧凑中文描述、JSON Schema 最小化，
  总 token ≤1200；Prompt Builder 在 A1 契约区尾部注入，**预算表增一行 ≤3%**，
  记忆检查器预算账目可见。
- A1 契约扩一句：「工具是旁路的结构化旁注，不是叙事的一部分；正文里不得描述工具使用；
  只为写进剧情的持久变化调用工具，瞬时状态留在正文里。」

### A2 轮末应用与事件化

- 消息落盘顺序固定为：**消息事件（含 tool_calls）→ 工具直写应用（origin=model）→
  各卡 on_message hooks → 轮末状态树/导演树求值**。单一固定顺序 = 重放确定性。
  群聊/隔离模式下按导演调度序逐角色应用，各角色工具只落自己作用域。
- 消息体存原始 tool_calls（名字 + 参数 JSON）；效果事件照常走既有通道
  （Blackboard/Memory/Thread/Codex proposal 等，origin="model"），重放按决断 3 推导。
- `ui_emit` 实时：流式解析到即经 `on_ui` 回调推前端 + `EffectEvent` 存档（origin=model），
  重放按序重演。

### A3 直写档六件（宿主确定性执行，全部过 hook 同款校验）

| 工具 | 语义 | 校验 |
|---|---|---|
| `psyche_feel(name, intensity, source)` | 情绪事件 | intensity 夹到 0–1；槽位 ≤3 封顶；走共用心理应用器（决断 7），接 M3.5 阈值链路 |
| `psyche_intent(goal, delta, source?)` | 意图新建/增减 | delta 夹到 −1–1；goal 非空 |
| `blackboard_set(key, value)` | 黑板公开字段 | key ∈ `BLACKBOARD_KEYS`；值深度 ≤8（照搬 hook 加固） |
| `memory_set(key, value)` | L3 事实键值 | 同 hook `api.memory.set` 语义 |
| `schedule_say(text)` | 下轮主动开口 | 非空；并入 `state.psyche.scheduled`（M3.5 通道） |
| `ui_emit(kind, value)` | 表情/立绘/音效 | kind 白名单同 hook |

### A4 提案档四件（复用收件箱链路）

| 工具 | 落地 |
|---|---|
| `propose_fact(target, facet, value, reason)` | `capture_grade` 分级：小事实按设置自动/询问，改写进收件箱；`anchors_conflict` 自动驳回 + diag |
| `propose_entity(kind, name, skeleton, reason)` | 全新实体 → 收件箱人工确认 |
| `propose_relation(from, to, kind, note, reason)` | 新关系 → 收件箱；悬空关系确定性校验 |

提案 id 沿用确定性格式（`<类>.<target>.<turn>.<i>`），重放幂等：撞上已 accept 的提案

### A5 校验、限额与诊断

- 每轮工具调用上限（settings，缺省 6），超出全弃 + diag 记一条汇总；

## 包 B · 故事时钟定时器（on_timer 落地）

### B1 定时器模型与求值

- 定时器声明进状态节点（糖，归一进树）：`timers = { { name=?, after_days=3, event="剧情无进展" } }`
  ——进入该状态时注册、离开时注销（重放由树投影推导，不落新事件类型，决断 5）。
- 轮末故事时钟推进后统一求值：到期 → 产生 `on_timer` 事件喂该角色状态树求值与
  on_message 同通道钩子；转移现身 `TransitionEvent`（reason=`timer:<名字>`）。
- `statetree.rs` `StateNode` 增 timers 字段与校验（名字重复、after_days ≤0 诊断）。

### B2 卡片动态定时器

- hooks 增 `api.after(n, "event:名")`（n 按故事天；`{ turns = m }` 按轮次）与
  `api.cancel_timer(名字)`；注册经 hook 增量回传（EffectEvent），重放重算。
- 同名重注册覆盖、注销不存在的名字静默；每会话活跃定时器上限 32。

**B 包 DoD**：「3 天后」构造用例跨轮触发 on_timer 转移且重放触发时刻一致；
全求值路径无系统时间参与（可注入时钟单测钉死）；线 deadline 行为不变（既有单测不改通过）。

## 包 C · 卡 Lua API 对齐（设计 §3.1 清偿）

### C1 读侧三件（回调式只读，非整库快照）

- `api.palace.recall(filter)`：宿主执行召回引擎（视角过滤按当前角色，M3.1 硬约束），
  filter = `{ topic?/place?/actor?/top_k? }`，返回摘要行数组；每 hook 调用次数上限 8。
- `api.codex.get(id)` / `api.codex.known(fact_id)`：单实体投影 / 揭示状态布尔。
- 实现形态：mlua 闭包捕获只读镜像（`card.rs` api 注册区，约 746–1225 行），
  每次调用有指令预算（沿用沙箱计费钩子）。

### C2 事件广播

- `api.trigger_event(name, data)`：排队到本轮末统一派发——在场所有角色的状态树求值
  与 hooks 各收到一次（事件名原样进 `when = "event:<名>"` 判据与 on_message 通道）。
- 公开性对齐「只共享说出口的与做出来的」：事件本身广播，触发者的卡私有 state 不随行
  （data 由卡作者显式构造）；触发记录走效果事件通道，重放重派发。

### C3 心理 API

- `api.psyche.feel(name, intensity, source)` / `api.psyche.boost_intent(goal, delta)`：
  与 A3 直写档共用心理应用器（决断 7）。

**C 包 DoD**：design.md §3.1 API 表逐项标注实现态（本包后全绿）；trigger_event 构造用例：

在隔离模式下按视角过滤（仅 witnesses 含当前角色的记忆可召回）。

**D 包 DoD**：OOC 驱动的状态树跳转/收线与面板操作走同一宿主命令（事件一致）；
`/ooc` 消息不进任何记忆通道（单测钉死）。

## 包 E · 旁白声道（非气泡叙事）

### E1 数据与渲染：旁白成为一等 voice

- `Message.role` 增 `"narration"`（`store.rs:347`；serde default 读旧值，老会话零迁移）。
  渲染层把旧插页（`role=system`）与新 narration 归入同一散文通道，样式统一抽出
  独立组件：无气泡、全宽、段落排版（衬线可选、弱背景或无背景、居中标题可选）——
  现有插页样式（SessionView.vue:681 一带）泛化复用。
- 摘要批次收录 narration（`BatchMessage::from_message` 增分支）；宫殿归属 witnesses =
  在场全体（决断 8）；L3/钩子不因旁白触发（旁白不是任何角色说的话——
  `apply_message_hook` 对 narration 跳过 on_message，`on_turn_end` 照常）。

### E2 宿主旁白生成点

- **场景接缝**：切场/分场/合场插页（`commands/scenes.rs:22`）从 system 迁到 narration
  通道，生成方式不变（现有实现），读侧兼容旧 system 插页。
- **阶段转移旁白**（新，可配开关）：状态树/导演树/世界主线阶段转移时，可选生成一段
  时代/氛围旁白（便宜档 provider 非流式调用，模板兜底——失败或未配 provider 时落
  一行模板句，不阻塞转移）。旁白落盘在转移事件之后、下一条消息之前。
- **剧场拍间**：剧场模式交叉剪辑的转场已有插页，纳入 narration 通道统一渲染，不新增生成点。

### E3 契约与边界

- A1 契约补一句：「narration 消息是客观叙事，不是任何角色的言行；角色的注入层与钩子
  不因旁白触发」。主演模型不产旁白（决断 8），本包不新增任何"让模型写旁白"的提示词通道。

**E 包 DoD**：旁白消息在三种主题预设下均为非气泡散文排版（dev 目检 + 截图）；
旁白进摘要、不触发 on_message（构造用例钉死）；阶段转移旁白在无 provider/调用失败时
模板兜底且转移不阻塞（单测钉死）；老会话（system 插页）打开渲染不回归。

## 包 F · 小说模式（互动式散文剧）

### F1 会话模式与渲染

- 会话级「小说模式」开关（建会话向导 + 会话设置各一处）：v1 仅 1v1 单场景可开
  （决断 9）。开启后：叙事模式锁小说体（A1 契约——第三人称、允许直陈心理，
  设计 §4.1 已有定义）；消息区切散文排版——char 消息不再逐条气泡，按段落流排版，
  角色对话织在段内（引号 + 「XX 说道」由模型按小说体自洽产出），narration/char
  同用 E 包散文组件，用户消息折叠为段间的「走向」提示条。
- 每段长度基调写入契约（缺省 300–800 字，可配）；段落结尾留钩子但**不替读者做决定**
  （契约明示：不得在正文里罗列"你可以……"——那是选项卡的职责）。

### F2 段末选项管线（新引擎件，最小实现）

- 一段 = 主演模型一次响应。段落落盘后触发**选项生成调用**：非流式、便宜档可配
  （未配则复用总结模型档）、max_tokens 小（≤300）。输入是紧凑上下文：现状卡 B1 +
  活跃线清单（标题/梯度/窗口摘要）+ psyche 意图 + 最近一段正文——
  选项必须"接得住悬置线"（至少一个选项关联活跃线，若有的话），不每段开新坑。
- 产出 3–4 个走向选项（`{ label, gist }`：界面短语 + 走向梗概），落 `Options` 事件
  （`LogBody` 第 14 类，origin=model）：沿管线产物先例随事件流重放，
  编辑历史重放**不重调模型**。
- 消费：用户点选 → 选项 gist 作为走向注入下一段（user 通道，标记来源=选项）；
  自由输入 → 原样作为走向。两者同构，模型无感区别。选项面板常驻自由输入框。

### F3 契约细节

- 用户输入定位（决断 9）：走向描述 + 引号直语两用。A1 小说模式条款明示：
  「用户消息是下一段剧情的走向；引号内的文字是角色的直接引语，须织入剧情；
  其余文字是走向指令，不得作为角色台词念出」。
- 选项生成调用失败/超时 → 段落照常，选项区显示自由输入（降级不阻塞）。

### F4 小说化导出（后处理的正确位置，决断 10）

- 导出命令：会话事件流重放 → 单文件 Markdown 小说（章节 = 场景，编年体；
  台词体会话同样可导出——转写由便宜档模型批量完成，段级重试、失败跳过留原文标记）。
- 只读导出，不写回会话；导出结果存 `sessions/<id>/novel.md` 或用户选择路径。

**F 包 DoD**：小说模式一段 → 选项卡 → 点选续写 → 自由输入续写全链路真机可玩；
选项事件重放一致（编辑段落重放后选项不变、不重调——单测钉死）；关闭小说模式回
台词体渲染无残留；导出对 200 轮压测会话可产出章节完整的 Markdown（真机跑一遍）；
未配选项档 provider 时降级为纯自由输入（单测钉死）。

## 节奏与风险

- **顺序**：A1–A2（底座）→ A3–A5（直写+校验）→ A6–A7（去重+UI）→ C → B → E → F → D。
  E 是 F 的地基（散文组件、narration 通道先行）；D 独立可裁可移 M4。
- **风险 1 · 模型工具质量参差**（幻觉参数/过度调用）：限额 + 校验 + diag 三层兜；
  设置页默认关、按接入点灰度。不做提示词之外的驯化投入，质量差就是不开。
- **风险 2 · SSE tool_calls 增量解析边界**：单独单测覆盖（部分 JSON/UTF-8 截断/
  content 与 tool_calls 交错），仿棘轮先例。
- **风险 3 · 与加固计划（hardening.md）并行冲突**：两者都动 `commands.rs` 发送路径——
  建议加固包 A（P0 崩溃项）先行，本计划随后；无强依赖，仅冲突面提示。
- **风险 4 · 双通道重复提案**：A6 去重 + 收件箱合并视图兜底；收件箱条目显示来源
  （model 工具 / pipeline 总结）。
- **风险 5 · 选项质量**（接不住线/每段开新坑）：F2 上下文强制携带活跃线清单 + 契约
  约束"至少一个选项关联活跃线"；真机验收构造用例：悬置约定存在时 4 个选项里至少
  1 个与之相关。质量不达标时的退路是关掉选项管线（纯自由输入不受影响）。
- **风险 6 · 每段多一次选项调用的延迟与费用**：选项生成异步（段落已可读）、
  便宜档、可整体关闭；不阻塞主链路。
- **风险 7 · 小说模式与既有机制的正交性**：psyche/线/宫殿/摘要对小说模式全部照常
  （散文也是消息流）；唯一新语义是用户输入定位（走向），真机构造用例点验
  「小说模式下约定仍被正确开线/收线」。
- **节奏预估**：A 包约占四成工时；E+F 合计约三成；整体 4–6 周（兼职节奏，对齐 M1–M3 实测）。

## 明确不做（本计划边界）

- 读查询工具（codex_get / palace_recall / threads_list 的续写环）——留 Backlog（决断 6）
- 真实世界时钟定时器——破坏重放确定性（决断 5）
- 模型任意 card state 写权、黑板任意键、宫殿直写——属主裁决不动（决断 1）
- 正文尾部结构块协议（弱模型兼容层）——解析健壮性差且与管线职责重叠，宁缺毋滥
- 工具调用的对话环内多轮协商（除未来读工具外）——RP 自报性质不需要
- 交互中的实时"扮演 → 小说"转写——双模型漂移与延迟，导出才是后处理的位置（决断 10）
- 群聊/剧场 × 小说模式组合、多场景小说——v1 限 1v1 单场景（决断 9）
- 台词体下让主演模型产旁白——旁白归宿主与模式所有（决断 8）
