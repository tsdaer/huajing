## 验收标准（DoD）

设计 §15 的 M4 条目（「他人无指导完成安装→导入→开聊；手机端能完成 1v1 对话」）落到可点验的形态：

1. **三包类型 zip 往返**：角色包 / 世界包 / 剧本包各一个构造用例——导出 → 清库 → 导入 →
   `get_card` / 设定集投影 / 建会话行为一致（单测钉死）
2. **拖入即装**：zip 拖入窗口走既有导入覆盖层，安装后热加载生效；路径穿越（zip slip）
   与超大单文件拒绝（单测钉死）；重复导入走 ST 卡的 overwrite 询问先例
3. **ST 反向导出**：canon 实体拍平为 ST 世界书 JSON（仅静态字段，§6.10），字段映射与
   导入侧互逆（单测对拍）
4. **签名更新闭环**：旧版本 exe 对着本地静态清单完成「检查 → 签名校验 → 下载 → 重启
   进入新版本」全链（真机构造用例）；签名不符拒绝安装；未配置端点时 UI 显示
   「自动更新未启用」且不报错
5. **宫殿睡眠整理**：低显著度相似记忆整理后——合并稿进对应场景卷摘要、原记忆退出召回、
   `palace.jsonl` 全量保留可溯源、事件流重放一致（单测钉死）；未配 util 档时手动整理
   提示未配置且零改动
6. **主题跟数据走**：自定义主题落 `DataHub/themes/`，拷走 DataHub 主题跟走；导出 → 清
   localStorage → 导入还原一致（旧 localStorage 值首启迁移）
7. **移动端 alpha**：Android（模拟器或真机）安装 APK → 文件选择器导入卡 → 建 1v1 会话 →
   流式对话 3 轮 → 杀进程重启会话完整；iOS 明示推迟（决断 6）
8. **无指导全流程**：干净用户目录安装 → 首启向导 → 导入角色包 → 开聊，走查清单逐项过
   （CDP 脚本 + 人工各一遍），首聊可达性与 M1 同标（≤ 3 分钟）
9. **流程 DoD**：CHANGELOG 更新 + README/设计文档同步 + `cargo test` 全绿（基线 492 +
   新增）+ `pnpm build` 双绿 + 0.3.1 / 0.4.0 两个定版 tag

## 关键架构决断

### 决断 1：更新无服务器——静态清单 + 签名校验，端点可配缺省关

Tauri 官方 updater 插件（内置签名校验）+ 静态 JSON 清单（Tauri v2 `latest.json` 格式）。
v1 先自用没有分发基础设施：客户端能力（签名、下载、校验、重启）先行，清单托管写成发布
流程文档（GitHub Releases 或任意静态托管皆可，非目标里的「云同步」不涉及）；端点进
`settings.toml` 可配，缺省空 = 自动更新未启用，UI 不报错只提示。

### 决断 2：包 = zip + pack.json 清单，spec 字段做前后兼容

`pack.json`：`{ spec: "huajing-pack/1", kind: "character"|"world"|"script", name,
creator?, description?, requires?: { world? } }`。加载器按 spec 做兼容（未来字段演进
只加不改）。导出永远从现有目录/投影打包，不改写库；导入复用 stimport 的
overwrite 询问 + find_similar 防重先例；解包前做 zip slip 防护与单文件大小上限。

### 决断 3：剧本包是会话模板，不是存档

内容 = premise + 初始黑板（世界层 + 默认场景分区）+ 导演树 director.lua（+
可选人格/模型档推荐），**不含消息历史与会话数据**——会话是本地隐私数据（§16-3），
分享会话存档不做。导入后建会话向导可选「剧本」，选中即把模板内容拷进新会话
（director.lua 落 `sessions/<id>/director.lua` 的既有机制）。

### 决断 4：宫殿整理是管线产物，不是钩子——触发可用真实时钟，产物随事件流重放

触发（手动按钮 / 空闲自动可配缺省关）依赖真实时钟**没关系**：整理产物是模型产物
（同 F2 选项先例——异步生成、落事件流、重放不重调模型），不是重放推导的状态。
流程 = 宿主确定性预分组（同 thread / 同 place / links 重叠阈值，候选 = 低显著度且
衰减后仍低于阈值）→ util 档 LLM 每组产一段合并稿 → 宿主校验（组 ≤8 条、稿非空、
actors/links 并集回填）→ 合并稿进对应场景卷摘要（Summary 事件）+ 原记忆打归档标记
（事件流记录）+ 新增合并记忆。`palace.jsonl` 永不物理删除。

### 决断 5：归档不复活

archived 记忆退出召回层（投影折叠），宫殿面板「已归档」过滤可查、可溯源跳原文；
「被再次提及则回升」（§5.4）只作用于未归档记忆。整理是一次性降层，不是软删除开关
——边界简单化，v1 不做「召回时复活归档记忆」的复杂语义。

### 决断 6：移动端 alpha 限 Android + 1v1，iOS 明示推迟

iOS 构建需要 macOS，本机无此环境，写明推迟不做假承诺。Android alpha 验收面 =
「安装 → 文件选择器导入卡 → 建 1v1 会话 → 流式对话 → 重启恢复」；群聊/剧场/素材
管线在移动端能打开但不进验收面。桌面拖放导入在移动端不可用 → 导入统一补文件
选择器入口（桌面同样可用）。数据目录走 `data_root` 既有第 4 档兜底。

### 决断 7：主题自定义迁 DataHub（themes/*.json），localStorage 首启迁移

主题块是机器生成的运行时数据（§16-5 归 JSON 侧，不进 settings.toml）；
`DataHub/themes/<名>.json`，拷 DataHub 即带走。首启检测 localStorage 旧自定义且
DataHub 无主题文件 → 自动迁移。主题不进三包格式（独立文件导入/导出，与包格式正交）。

## M4.1 · 包格式与导入导出（主体）

### pack.rs 内核

- pack.json schema 校验（spec 不认识 → 拒绝并报支持的最高版本；kind 三选一；
  name 必填非空）；zip 打包（固定目录布局，见决断 2 三包各自内容）；解包防护
  （zip slip：entry 规范化路径必须落在目标目录内；单文件 ≤64MB；entry 总数上限）
- 三包布局：角色包 `card.lua + assets/ + entities/ + pack.json`；世界包
  `world.json + worldline.lua + entities/ + grown.json + pack.json`；剧本包
  `pack.json + premise.toml + blackboard.initial.json + director.lua`

### 导入

- `import_pack(path)`：识别 kind → 按 stimport 先例落目录（角色进 `characters/<名>/`、
  世界进 `codex/<世界>/`、剧本进新目录 `scripts/<名>/`）→ 热加载生效（卡走 watch
  既有通道；世界导入后 codex 缓存按指纹自动重建）→ 重复名走 overwrite 询问 +
  find_similar 提示
- 前端：拖入窗口复用既有导入覆盖层，分流 ST 卡（PNG/JSON）与包（zip）；剧本包
  导入后在建会话向导出现「剧本」选择，选中即拷模板进新会话（决断 3）

### 导出

- 角色导出：卡目录整打包（含 assets/entities，pack.json 现场生成）
- 世界导出：`codex/<世界>/` 整打包（world.json/worldline.lua/entities/grown.json）
- 剧本导出：从既有会话抽取——premise、当前黑板投影的**初始形态**（用户编辑后保存为
  模板起点）、导演树 director.lua → `scripts/<名>/` + 打包 zip
- **ST 反向导出**（§6.10）：`export_worldbook_st(world)`——canon 实体拍平为世界书
  JSON（name→title/首别名→key/文本→content，仅静态字段；versions 取现行值、
  retired 不导），字段映射与导入侧互逆（单测对拍：导出 → `parse_worldbook` → 回读一致）

**M4.1 DoD**：三包往返构造用例（导出 → 删目录 → 导入 → get_card/投影/建会话一致，
单测钉死）；zip slip / 超大 entry 拒绝（单测）；拖入安装真机走查；ST 世界书导出
对拍单测；新增 `zip` 依赖进 Cargo.toml（唯一清单变更之一）。

## M4.4 · 宫殿睡眠整理

- **候选与分组（宿主确定性）**：候选 = salience 衰减后仍 < 阈值（settings 可配，
  缺省 0.25）的 episode/hearsay；按（同 thread → 同 place → links 重叠 ≥2）优先级
  贪心分组，组 ≤8 条、不足 2 条不成组
- **合并稿（util 档 LLM）**：每组一次调用，输入 = 组内记忆原文 + 时间/actors/links，
  产一段 100–200 字合并稿；失败/空稿/超长 → 该组放弃不阻塞其他组

## 节奏与风险

- **顺序**：M4.0（定版）→ M4.1（包格式主体）→ M4.2（更新器）→ M4.3（主题小包）→
  M4.4（宫殿整理）→ M4.5（移动端）→ M4.6（收口）。M4.3/M4.4 可互换；M4.5 依赖前四包
  定型（避免移动端返工），但若 Android 环境受阻，M4.5 可与 M4.6 换序，桌面收口先行。
- **风险 1 · 更新器真机构造成本**（要造旧/新两版 exe）：用 debug 构建降成本——
  updater 只要求包签名与清单格式正确，不要求 release 优化；构造版直接改版本号重编。
- **风险 2 · zip 边界安全**：zip slip / 超大 entry / 深层嵌套目录各有单测钉死；
  解包一律走白名单布局校验（pack.json 声明的目录之外拒绝）。
- **风险 3 · Android 环境不在手**：SDK/NDK 下载体积大、模拟器慢；缓解 = M4.5 前半
  （响应式 + 文件选择器）在桌面窄窗全部完成，Android 构建单独成步；实在受阻时
  记录环境障碍，M4.6 桌面收口不受阻塞（ROADMAP 注记移动端顺延）。
- **风险 4 · 宫殿整理质量**（合并稿失真）：组 ≤8 条小批量 + 合并稿带原文溯源
  （面板可跳原记忆对质）+ 整理默认手动触发（自动缺省关）；质量不行用户不开即可，
  不阻塞其他包。
- **风险 5 · 版本三处漂移**：M4.0 补一致性断言单测后，漂移在 CI/test 层即红。
- **节奏预估**：M4.1 约三成工时；M4.2/M4.4/M4.5 各约两成；整体 4–6 周（兼职节奏，
  对齐 M1–M3 实测）。
