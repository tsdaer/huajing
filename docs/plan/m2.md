## 关键架构决断（M2 的地基）

### 决断 1：事件日志是唯一事实来源（M2.0，先做）

ROADMAP 已明示「M2 启动前先做事件日志」。M1 遗留的同源问题——**钩子对 state 的改动没有回滚语义**
（编辑/删除历史消息后好感度不会退回）——只有事件溯源能根治，且 §7.3「可回放」、§6.9「确认动作入流」、
§5.3「批次可从 jsonl 回放重算」都指向同一份设施。

- `messages.jsonl` 升级为**类型化事件流**：`message`（旧行无 `kind` 字段，按消息读，向后兼容）
  / `effect`（钩子副作用：state 快照、黑板写入、记忆写入）/ `transition`（状态树转移）
  / `thread`（开线·推进·收线）/ `codex`（揭示·确认·retcon）/ `blackboard`（手动改与时钟步进）。
- **投影（projection）** = 事件流的纯函数折叠：消息列表、各角色 state、黑板、宫殿、剧情线、设定揭示集。
  派生文件（`state.json` / `blackboard.json` / `palace.jsonl` / `threads.json`）一律由投影写出，
  **不再由调用点分头写**——落盘只有一条路径，回放必然一致。
- **消息级操作的语义**：编辑/删除第 T 轮消息 → 保留消息事件、丢弃 T 轮起的 `effect` 事件，
  再按卡顺序重跑 T 轮起的钩子，追加新 `effect` 事件。钩子是 (事件, 黑板, state) 的纯函数，
  重放得到同一状态（§7.3-5）。
- 新增命令 `replay_session`（诊断/调试）与 `session_timeline`（事件流视图）。

### 决断 2：三分工不越界

| 谁 | 管什么 | 不管什么 |
|---|---|---|
| 宿主（Rust，确定性） | 转移求值、召回打分、激活解析、窗口与冷却、衰减与阈值 | 不生成文本、不猜剧情 |
| LLM（便宜档 provider） | 总结、捕获提案、时机起草、评价提案 | 不直接改正史与状态（走收件箱） |
| 玩家 | 确认/否决/改写提案、手动开收线、手动改设定 | —— |

### 决断 3：模块边界

```
src-tauri/src/
  event.rs       # M2.0 事件流：记录类型 / 投影 / 重放 / 重建
  palace.rs      # M2.1 记忆宫殿：记忆对象、显著度衰减、视角过滤、召回打分、三视图
  codex.rs       # M2.2 设定集：实体 schema、别名索引、五激活源、三级注入、anchors/variants/live
  statetree.rs   # M2.3 状态树：状态/转移/directive/reveal/recall、轮末求值、事件驱动
  threads.rs     # M2.4 剧情线：生命周期、提及时机窗口、冷却、升格、投影
  psyche.rs      # M2.5 心理运行时：情绪槽、气质参数、衰减、意图强度、外化
  summarize.rs   # M2.6 自动总结管线：滑窗淘汰触发、LLM 调用、提案落收件箱
  prompt.rs      # M2.7 改造：A/B/C 全槽位 + 预算分配 + 逐层降级 + token 记账
```

约定：**Lua 只在 card.rs 的沙箱里跑**（状态树转移、设定集条件、卡钩子）；其余模块是纯 Rust 数据与算法，
不碰文件、不碰网络——因而都能被单测直接钉住。

## 任务分解（按依赖序）

### M2.0 事件日志与重放 ✅

- `event.rs`：`LogRecord`（kind 判别 + 旧行兼容）、`Projection`、`project()`、`rebuild_from(turn)`
- `store.rs`：`EventLog`（字节偏移增量读 + 追加 + 失效）取代 `MessageLog` 的落盘职责
- `commands.rs`：钩子副作用改记事件；派生文件由投影写；`edit_message` / `delete_message` 走重建
- **验收**：同一事件流两次投影结果相同；编辑带「谢谢」的消息后 `favorability` 回退；
  删除末轮后 state/黑板/宫殿与「从没发生过」一致（M1 遗留 #7 关闭）

### M2.1 记忆宫殿 alpha ✅（引擎 + B4 接入；面板与睡眠整理归 M2.8/M4）

- 记忆对象 v1：`kind/content/time/place/actors/witnesses/salience/emotion/links/thread`
  （M1 的 `fact` 记录按读侧兼容并入，不破坏旧 `palace.jsonl`）
- 召回打分 = 视角过滤 → salience × 故事时间衰减 × 关联命中（recall 提示/地点在场/最近提及/活跃线）
  × 再提及增强 → top-K；`recall` 钩子留给卡覆写
- 三视图数据：房间（地点）/ 时间线 / 关联图；每条可溯源到 turn
- **验收**：召回打分单测（时间衰减、视角过滤、关联命中、再提及增强各一例）；
  面板数据能画三视图；B4 槽按「回忆」框架注入且带故事时间戳

### M2.2 设定集 v1 🔄（实体 schema/激活/分级注入/anchors/variants/versions 已落地并接入 B3；ST 世界书导入与收件箱 UI 待做）

- 实体 schema（`.lua` / `.json` 双格式）：char/place/item/event/org/rule/concept/note 模板
- 别名倒排索引（自建 trie，不引依赖）→ 提及激活；在场 / 揭示 / 关系牵引 / 常驻四源
- 三级注入深度 + 滞回（默认 3 轮）；`look.anchors` 恒注入且最高保护级；`live` 从黑板取 `▸当前`
- `variants` 条件变体（按黑板/时钟确定性选择）；`versions` 史变版本流（按故事时钟解析）
- 草稿/正史/`retired` 生命周期 + `proposals.jsonl` 收件箱（diff 数据）
- ST 世界书 JSON → `note` 实体导入
- **验收**：五激活源各一例；分级深度与预算降级顺序可回放；anchors 冲突提案被驳回；
  同一实体的第 10 天 / 第 30 天解析出不同事实版本；token 占用随深度可测

### M2.3 状态树 v1 ✅（引擎 + B2/reveal/recall 接入；导演树与 Consideration 打分属 M3/v2）

- 卡内 `state_tree`：`root/states/parent/directive/transitions({to,when,priority})`
  `on_enter/on_exit`、`recall`、`reveal`
- 轮末求值（一轮内稳定）、祖先转移继承、priority 升序首个命中、转移事件入事件流
- 判据可查：黑板、角色 state、`codex.known(...)` / `codex.active(...)`、`threads.active/resolved`
- **验收**：示例树（日常→夜谈→释然）跑通；转移是事件的纯函数（重放同路径）；
  恶意转移（死循环/抛错）被沙箱杀掉且降级为原地不动

### M2.4 剧情线 v0 ✅（引擎 + B1/C1 接入；开线提案的 LLM 起草归 M2.6）

- `threads.json` 模型（起因/经过/结果 + `resurface` 时机）+ 事件溯源落盘
- 生命周期：开线（premise/手动/树任务/管线提案）→ 推进 → 升格（deadline → `thread:due`）→ 收线/放弃
- 收线三件事：高显著结果记忆入宫殿、`thread:<id>:resolved` 事件、移出现状卡
- 提及时机：`grade`（dormant/natural/eager）× `windows`（黑板/mention/actors_with/状态路径）× `cooldown`

- **验收**：窗口未命中时现状卡不出现该线（「不强行提起」）；deadline 到期抛事件并升格；
  收线后结果记忆与状态转移同时发生

### M2.5 心理运行时 v0 ✅（引擎 + B5 接入；`api.psyche` 沙箱 API 与面板归 M2.8）

## 节奏与风险

- **顺序**：M2.0 必须先落地（改的是落盘路径，越晚改代价越大）；M2.1/M2.2/M2.3 可并行开发但按此序集成；
  M2.4/M2.5 依赖 M2.3 的事件与 M2.1 的宫殿；M2.6 依赖 M2.1/M2.4/M2.2 的写入端；M2.7 收口；M2.8 跟随。
- **风险 1：LLM 产物不稳定** → 一切 LLM 产物先落草稿，注入只认 canon（§6.9）；
- **风险 2：提示词膨胀** → 预算表 + 降级顺序在 M2.7 前先用干跑预览量化，超预算即降级而不是硬塞；
