# M3 执行计划 · 热闹、会长大、有节奏、不串台（0.3.x）

> 对应 [ROADMAP](../../ROADMAP.md) M3 · 设计依据 [design.md](../design.md) §10（多智能体与场景隔离）§6.6（世界主线）§6.7（素材规格化）§6.8（设定补全）§8.6（导演树）§9.2–9.3（意图与外化）§12（数据目录）§15（里程碑）
> 一句话目标：**多角色同台不串台、世界跨会话会长大、wiki 一贴十分钟成卡、导演控得住节奏。**

## 验收标准（DoD）

设计 §15 的 M3 条目逐条落到可点验的形态：

1. **3 角色群聊不冷场、不打架**——发言权调度可见（谁在说话、为何轮到她），无两角色同轮抢话，
   无连续 N 轮同一人独占（导演面板可查调度依据）
2. **剧场模式自动跑 20 轮且至少完成一次完整的开线→收线弧**——导演树起承转合推进，
   转移历史可回放
3. **角色主动行为可溯源到意图**——主动消息/外化开线在心理面板能指回意图条目
   （强度、linked_thread、触发阈值）
4. **串台构造用例：隔离模式下，仅 A 见过的事实不出现在 B 的任何注入层**——B4/B3 深卡/
   揭示集逐层断言（单测钉死 + 检查器可点验）
5. **"与此同时"多线切换与合场可用**——切场有过渡提示、被切走场景冻结、合场时黑板分区合并
   而各角色记忆不合并
6. **跨会话：世界时钟与主线阶段持久推进**——会话结束回写世界层；回忆场景按故事时钟取到
   旧版事实（versions）
7. **wiki 角色页粘贴导入 → 10 分钟内产出可开聊角色**——含引源审阅与切入点选择；
   切入点正确初始化秘密知情集（known_by）与实体状态（lifecycle/versions 取值）
8. **设定收件箱可用**——提案 diff、冲突双源呈现、批量处理、确认写正史进注入
9. **手动补全 1 分钟产出一个与既有设定一致的角色**——实体编辑器缺失 facet 高亮 +「补全」
   按钮，生成规范内嵌写作论约束（anchors 宁少而精、口癖落进示例对话、tells 覆盖高频情绪）
10. **流程 DoD**：CHANGELOG 更新 + README/设计文档同步 + `cargo test` 与 `pnpm build` 双绿 +
    真机验收（沿用 M2 的 CDP 自动化夹具）

## 现状盘点（写计划时的地基）

M2 留下的资产让 M3 不必从零开始：

- **数据模型早已预留多智能体**：`Message.scene_id: Option<String>`（现恒 None）、
  `SessionMeta.characters: Vec<String>`（现单元素）、secrets 的 `known_by: Vec<String>`、
  记忆对象的 `witnesses`——M3 主要是把这些字段用起来，无破坏性迁移
- **每角色隔离的引擎件已就位**：宫殿召回按 viewer 过滤（M2.1）、状态树/state 按角色分键（M2.0 投影）、
  B 槽组装是纯函数（M2.7）——隔离模式 = 把「一次组装」变成「按角色 N 次组装」
- **worldline 不造新引擎**：状态树引擎 + 线模型直接换作用域（设计 §6.6 明示）
- **P0–P11 提示词套件已入库**（`docs/prompts/ingestion-prompts.md`），M1 起可零代码手用；
  M3.9 是把它接进 App 内管线

## 关键架构决断（M3 的地基）

### 决断 1：场景是隔离的顶层单元，先分段后隔离

消息流按 `scene_id` 分段（老会话 None = 默认场景，读侧归一）；黑板拆世界层 + 场景分区
（现有平铺键归世界层，向后兼容）；滚动摘要按场景分卷 + 世界层大事记（仅公开事件）。
**先做场景再做群聊**：群聊只是"单场景多角色"，剧场才是"多场景调度"——同一套分段设施复用。

### 决断 2：隔离模式是组装策略，不是新引擎

每轮发言 = 该角色独立的上下文组装与独立请求（自己的黑板分区 + 世界层、自己的宫殿视角召回、
自己的 psyche/状态树/known_by）；其他角色对他只是消息流里的台词与动作。
**1v1 自动退化为共享模式**（开关降级，不浪费）。三分工不变：宿主管调度与隔离边界，
LLM 只演，玩家确认。

### 决断 3：导演是元层，输出只产生调度动作

导演（含 LLM 导演 agent）可见全局用于调度，但其输出只有：切场/点名/时间推进/开收线/合场裁决。
**调度动作绝不进入任何角色的上下文**——落事件流（`director` 类事件），回放可重现整场调度史。
发言权打分是宿主侧确定性算法（最近提及、所在场景黑板、活跃线关联、`want_to_speak` 投票加权），
LLM 导演只是可选的高层策略源。

### 决断 4：转述（hearsay）是信息跨视角的唯一通道

剧情中 A 把某事告诉 B 时，管线为 B 生成 hearsay 记忆（source=A、salience 折半、links 继承）。
秘密揭示 = reveal 把该场景见证者加入 `known_by`；深卡注入按"当前组装视角是否知情"判定。
**不在提示词里恳求"不要串台"，用数据结构让串台不可能**（设计 §10.1）。

### 决断 5：规格化与补全都走草稿→确认，anchors 最高保护

素材管线（§6.7 八步）与补全管线（§6.8 四机制）共用「写入时智能」框架：全部产物 draft、
逐条引源、收件箱 diff 审阅；一致性校验（id 重复/字段冲突/悬空关系）确定性先行，
anchors 冲突直接驳回。即兴模式默认关、opt-in，会话结束统一进收件箱。

### 决断 6：M3.0 先清偿 M2 遗留

真机验收的 6+1 项非阻断遗留（m2.md 结项小结）在铺开新架构前清掉——其中⑤⑥⑦是引擎侧债，
越晚还利息越高（⑤时间戳失真会随批次累积、⑥记忆堆叠稀释召回、⑦重放丢转移违背可回放承诺）。

## 模块边界（新增）

```
src-tauri/src/
  scene.rs      # M3.2 场景：分区黑板、消息流分段、切场/分场/合场、局部时间线
  director.rs   # M3.4/M3.6 导演：发言权打分、调度队列、导演树（起承转合）、交叉剪辑
  worldline.rs  # M3.7 世界主线与世界时钟：跨会话持久、阶段弧、世界级线
  ingest.rs     # M3.9 素材规格化：八步管线、切入点向导、P0–P11 按阶段调用
  complete.rs   # M3.8 设定补全：模板补全、一致性校验、即兴模式、收件箱写回
```

既有模块的改造集中在：`prompt.rs`（按角色组装 + 场景分区投影）、`commands.rs`（隔离模式发送
与调度循环）、`codex.rs`（known_by 视角化解析）、`summarize.rs`（摘要分卷 + hearsay 生成 +
⑤事发时间戳）、`event.rs`（`director`/`scene` 事件类型 + ⑦重放语义）。
约定不变：Lua 只在 card.rs 沙箱跑；新模块纯 Rust 数据与算法，不碰文件不碰网络，单测直接钉住。

## 节奏与风险

- **顺序**：M3.0 清偿 → M3.1 隔离（一切多角色设施的地基）→ M3.2 场景 → M3.3 视角 →
  M3.4 群聊 → M3.5 主动 → M3.6 剧场（主线 A，严格依序）；M3.7 worldline 依赖 M3.2 的世界层黑板；
  **M3.8 补全与 M3.9 素材是支线 B**，不依赖场景架构，可与主线 A 交错开发（先 B 后 A 亦可）；
  M3.10 收口。预计是四个里程碑里最长的一个，支线 B 先行可以在主线 A 卡壳时切换战场。
- **风险 1：隔离模式请求成本 ×N** → 每轮发言数由导演限流（默认 1–2）；1v1 自动退化；
  群聊可退回共享模式软约束（A1 契约）先跑通再开隔离
- **风险 2：场景分段的兼容性** → `scene_id` 已是 Option（老会话 None = 默认场景）；
  黑板现有平铺键归世界层不做迁移；投影读侧归一
- **风险 3：调度确定性** → 发言权打分全宿主侧确定性算法，LLM 导演只是可选策略源且
  输出必经调度动作白名单；一切调度落 `director` 事件，回放可重现（与 M2 的可回放承诺同构）
- **风险 4：素材管线产物质量参差** → 全部 draft + 逐条引源 + anchors 显式确认；
  分类不确定归"待定"宁漏勿错；机制数据默认过滤
- **风险 5：worldline 与个人线的纠缠** → worldline 可缺省（纯日常世界照常运转）；
  主线只开世界级线（scope: world），个人线照常开合——框架与戏分离
